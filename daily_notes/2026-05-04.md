## What I studied

### Core LangChain concepts

**1. The pipe pattern**
```python
chain = prompt | llm | parser
chain.invoke({"variable": "value"})
```
Three bricks connected with `|`. Each brick's output feeds the next automatically.

**2. Prompt Templates**
- Reusable prompts with named variables in `{curly braces}`
- Saved as `.txt` files — prompts and code stay separate
- Load with `open("prompts/file.txt").read()`

**3. Model**
```python
llm = ChatOpenAI(model="gpt-4o", temperature=0)
```
Swapping to Anthropic = change 2 lines, everything else stays the same.

**4. Output Parsers**

| | `JsonOutputParser` | `with_structured_output()` |
|---|---|---|
| Returns | Plain dict | Pydantic object |
| Schema enforcement | Lenient | Strict |
| Needs "return JSON" in prompt | Yes | No |

Access Pydantic fields with `result.fit_score` instead of `result["fit_score"]`.

**5. Multi-chain pipeline**
```python
jd_chain    = jd_prompt    | llm.with_structured_output(JDRequirements)
resume_chain = resume_prompt | llm.with_structured_output(ResumeProfile)
fit_chain   = fit_prompt   | llm.with_structured_output(FitEvaluation)

def evaluate_pipeline(job_description, resume):
    jd_data     = jd_chain.invoke({"job_description": job_description})
    resume_data = resume_chain.invoke({"resume": resume})
    result      = fit_chain.invoke({
        "jd_requirements": jd_data,
        "resume_profile": resume_data
    })
    return result
```

Pass Pydantic objects between chains directly — no need for `.model_dump()` when using `with_structured_output()`.

---

## Key lessons learned

1. **Prompt and schema must agree** — the model follows prompt instructions more than the schema. If you want `fit_score` 0–10, say so in the prompt.
2. **`with_structured_output()` enforces field types, not value ranges** — range constraints live in the prompt, not the schema.
3. **Separate prompts from code** — save prompts as `.txt` files, load at runtime.
4. **`model_dump()`** converts a Pydantic object to a plain dict when needed.
