## What I studied

### What is an embedding?
- A list of numbers (vector) that represents the **meaning** of a piece of text
- Texts with similar meaning have similar vectors — measured by cosine similarity
- Generated by a dedicated embedding model (`text-embedding-3-small`), not an LLM

### Embedding model vs LLM

| | LLM (gpt-4o) | Embedding model |
|---|---|---|
| Output | Text | Vector (numbers) |
| Purpose | Reasoning, generation | Semantic similarity |
| Speed | Slow | Fast |
| Cost | Expensive | Cheap |

### The full workflow
```
Phase 1 (once): embed 500 JDs → store in FAISS
Phase 2 (each query): embed resume → search FAISS → return top N matches
```

Vector search narrows 500 JDs → top 10. LLM evaluation ranks top 10 → top 3.

## What I built

### FAISS vector search pipeline
```python
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vector_store = FAISS.from_texts(job_descriptions, embeddings)
results = vector_store.similarity_search_with_score(resume, k=3)
```

### Similarity score threshold
- FAISS uses L2 distance — lower score = more similar
- Engineering resume scores: 0.81 – 0.96 (relevant)
- French chef scores: 1.44 – 1.55 (irrelevant)
- Threshold set at **1.2** — anything above = no match

### Persistence — save and load index
```python
# Save (embed once)
vector_store.save_local("faiss_index")

# Load (no API calls on subsequent runs)
vector_store = FAISS.load_local("faiss_index", embeddings,
                                allow_dangerous_deserialization=True)
```

---

## Key lessons

1. **Vector search always returns results** — never says "no match". Must set a threshold manually.
2. **Embed once, search many times** — save the FAISS index to disk to avoid re-embedding on every run.
3. **Embedding is not LLM** — it's a separate, cheaper model that converts text to numbers.
4. **Two-layer search**: embedding search (fast, cheap) → LLM evaluation (slow, expensive).
