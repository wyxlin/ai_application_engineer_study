## What I studied

### 1. The OpenAI Client

```python
from openai import OpenAI
client = OpenAI()  # reads OPENAI_API_KEY from environment automatically
```

- `client` is the connection object — the "phone" your Python program uses to talk to OpenAI
- `client.responses.create(...)` sends one request and gets one response back

### 2. Core Parameters of `client.responses.create()`

| Parameter | Role | Example |
|---|---|---|
| `model` | Which model to use | `"gpt-4o"` |
| `instructions` | Model's role, rules, behavior (system-level) | `"You are a patient AI tutor."` |
| `input` | The user's current request | `"Explain REST vs gRPC."` |

```python
response = client.responses.create(
    model="gpt-4o",
    instructions="You are a patient AI tutor.",
    input="Explain the difference between REST and gRPC."
)
print(response.output_text)  # easiest way to read the answer
```

- `response` is the full result object
- `response.output_text` is the final text answer

### 3. API Key Security

- Never hardcode the key in your source code
- Store it in a `.env` file or shell environment variable
- Load it in Python with `load_dotenv()` from `python-dotenv`

```python
from dotenv import load_dotenv
load_dotenv()  # loads .env into environment — must be called before OpenAI()
```

- Add `.env` to `.gitignore` so it never gets pushed to GitHub

### 4. Three Ways to Write `input`

**Simple string** — one message, no role needed:
```python
input="Explain what an API is."
```

**Message list** — conversation history or multi-role input:
```python
input=[
    {"role": "user", "content": "Explain REST vs gRPC."}
]
```

**Content-part list** — multimodal (text + image or file):
```python
input=[
    {"role": "user", "content": [
        {"type": "text", "text": "What is in this image?"},
        {"type": "image_url", "image_url": {"url": "..."}}
    ]}
]
```

Use **message list** when you need conversation history or multi-turn context.
Use **simple string** for quick single-turn calls.

### 5. Modern Control Knobs (not `temperature`)

For the modern Responses API, focus on:

| Knob | Purpose |
|---|---|
| `reasoning.effort` | How hard the model thinks (`"low"`, `"medium"`, `"high"`) |
| `text.verbosity` | How long/detailed the response is |
| Structured Outputs | Force JSON schema compliance |

`temperature` is a lower-level concept — not the main control knob for application-level work.

### 6. Classification — First Concept

**Classification** = putting user input into predefined categories so your program can decide what to do next.

Example: user says `"I want to delete my account"`
→ model classifies it as `category: account_management`, `intent: delete_account`
→ your code routes it to the account deletion workflow

This is the foundation of multi-step AI systems — the model decides the path, your code executes it.

---

## Key takeaways

1. `instructions` = who the model is. `input` = what you want right now. Keep them separate.
2. Always use `.env` for API keys. Never commit secrets to git.
3. Message list format is the natural way to represent multi-turn conversations — get comfortable with it early.
4. Classification is how an AI system stops being a single chatbot and starts being a decision engine.
