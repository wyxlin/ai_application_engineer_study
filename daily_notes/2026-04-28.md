## What I studied

### 1. Base LLM vs Instruction-Tuned LLM

- **Base LLM**: predicts next token based on training data. Unpredictable for tasks.
- **Instruction-tuned LLM** (what you use via API): fine-tuned + RLHF to follow instructions. This is GPT-4o, Claude, etc.
- Practical takeaway: always think of the model as a capable assistant that follows explicit instructions — the quality of your output is bounded by the quality of your instruction.

---

### 2. Two Core Principles of Prompting

#### Principle 1: Write clear and specific instructions

| Tactic | What it does | Example |
|---|---|---|
| Use delimiters | Isolate input from instruction, prevents prompt injection | ` ``` `, `"""`, `<text></text>` |
| Ask for structured output | Get JSON/HTML back instead of prose | "Return a JSON with keys: title, score, reason" |
| Check conditions first | Tell the model to handle edge cases explicitly | "If the text has no job requirements, return `null`" |
| Few-shot examples | Show the pattern you want before asking | Give 1–2 input/output examples in the prompt |

#### Principle 2: Give the model time to think

| Tactic | What it does |
|---|---|
| Specify steps | "Step 1: extract…  Step 2: evaluate…  Step 3: return JSON" |
| Ask model to reason before concluding | "Work out your answer before stating the final result" — reduces wrong confident answers |

---

### 3. Iterative Prompt Development

The prompt is never perfect on the first try. The process:

```
Write prompt → See output → Identify gap → Refine → Repeat
```

Key habits:
- Start simple, add constraints only when you see a real failure
- Test on multiple inputs before settling on a prompt version
- Track prompt versions (your repo is the right place for this)

### 4. Core Task Types

| Task | Key Prompt Pattern |
|---|---|
| **Summarizing** | "Summarize in under 50 words, focus on X" |
| **Inferring** | "What is the sentiment? What topics are covered?" |
| **Transforming** | "Translate to French" / "Convert to JSON" / "Fix grammar" |
| **Expanding** | "Write a reply to this email in a professional tone" |

### 5. Building a Chatbot — The Messages Format

This is how the API actually works:

```python
messages = [
    {"role": "system",  "content": "You are a helpful assistant."},
    {"role": "user",    "content": "What is RAG?"},
    {"role": "assistant","content": "RAG stands for..."},
    {"role": "user",    "content": "Give me an example."},
]
```

- **system**: sets the model's persona and constraints — runs once, shapes all responses
- **user**: what you send
- **assistant**: what the model replied (include prior turns to give the model memory)
- Without prior turns in `messages`, the model has no memory of the conversation

---

### 6. Temperature

- `temperature=0`: deterministic, same output every run — use for structured extraction, evals
- `temperature>0` (0.7–1.0): creative, varied output — use for brainstorming, writing

## Key takeaways for your roadmap

1. **Structured output is the foundation of AI application engineering.** Prose output is hard to use downstream; JSON is composable. Always design your prompt to return structured data when another piece of code will consume it.
2. **Delimiters prevent prompt injection.** When user content is inserted into a prompt, always wrap it: `<job_description>{jd}</job_description>`.
3. **The messages format IS the API.** Understanding system/user/assistant roles is prerequisite knowledge for everything else — LangChain, agents, memory, all build on top of this.
4. **Temperature=0 for your job evaluation pipeline.** You want consistent, comparable scores across jobs.
