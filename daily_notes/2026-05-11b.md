## What I studied

### Chunking — new concept
Long documents can't be embedded as one piece — the embedding averages everything together and loses precision. Solution: split into smaller chunks before embedding.

```
Full resume (2000 words)
    ↓
RecursiveCharacterTextSplitter(chunk_size=300, chunk_overlap=50)
    ↓
Chunk 1: Education (200 words)
Chunk 2: Skills (150 words)
Chunk 3: Project 1 (300 words)
...
    ↓
Embed each chunk → store in FAISS
```

`chunk_overlap=50` means adjacent chunks share 50 characters — prevents losing context at chunk boundaries.

### Three new tools
| Tool | Purpose |
|---|---|
| `TextLoader` | Loads a `.txt` file as a LangChain document |
| `RecursiveCharacterTextSplitter` | Splits documents into chunks |
| `FAISS.from_documents()` | Embeds chunks and stores in FAISS |

## What I built

Portfolio Document QA system (`projects/rag/portfolio_qa.py`):
- Loads resume as a text file
- Splits into chunks with `RecursiveCharacterTextSplitter`
- Embeds chunks and stores in FAISS with persistence
- Answers questions grounded in resume content

### Sample outputs
- "What distributed systems experience?" → gRPC systems, Distributed OS coursework
- "What languages?" → Java (Expert), Python, SQL
- "What AI experience?" → LLM agents, Claude/Codex, prompt engineering

---

## Key lessons

1. **Chunk long documents before embedding** — never embed a full document as one vector
2. **chunk_overlap** prevents losing context at boundaries
3. **`langchain_text_splitters`** is a separate package from `langchain_community`
4. RAG over personal documents = Portfolio Document QA — a real portfolio project
